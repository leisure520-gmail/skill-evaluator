# 轨道一：单文件质量评估

评估单个 Skill 文件的写作质量。8 个加权维度，0-10 分制，S 级（>= 9.0）为唯一达标等级。

> **评分标准唯一来源**：`templates/dimensions.md`。多模型模式时，Prompt 模板详见 `templates/prompts.md`，报告格式详见 `templates/report-formats.md`。

---

## 8 维度评估框架

> 每个维度的**评分细则**（0-10 分各档标准）详见 `templates/dimensions.md`。以下仅列出各维度的**检查项清单**，用于逐项确认通过情况。

### D1：元数据质量（权重 15%）

YAML frontmatter 中 `name` 和 `description` 的质量。

| # | 检查项 | 通过标准 |
|---|--------|---------|
| 1.1 | frontmatter 包含必要字段 | name/description/status/version 齐全 |
| 1.2 | name 简洁且唯一 | kebab-case，无歧义 |
| 1.3 | description 精确描述用途和边界 | 包含功能描述 + 边界限定 |
| 1.4 | description 包含触发关键词 | 包含 2+ 个触发场景关键词 |
| 1.5 | status 与实际内容一致 | published = 内容完整可用 |

### D2：执行引导清晰度（权重 15%）

Skill 加载后，AI 是否清楚该执行什么、按什么顺序、遇到异常怎么办。

| # | 检查项 | 通过标准 |
|---|--------|---------|
| 2.1 | 有明确的加载声明 | AI 知道加载后第一步做什么 |
| 2.2 | 有 Pre-Flight 预检清单 | 关键前置条件不遗漏 |
| 2.3 | 执行步骤有序且无歧义 | 编号/箭头/流程图，无"看情况" |
| 2.4 | 有异常/分支处理指引 | 关键分支有明确处理路径 |
| 2.5 | 有 Post-Flight 验证 | 产出物可验证 |

### D3：领域知识密度（权重 15%）

Skill 是否内嵌了通用 Agent 不具备的专业知识、最佳实践和行业规范。

| # | 检查项 | 通过标准 |
|---|--------|---------|
| 3.1 | 包含专业领域知识 | 通用 Agent 不知道的专家知识 |
| 3.2 | 包含最佳实践和反模式 | do/don't 对照明确 |
| 3.3 | 知识有具体示例 | 不是空谈，有可执行示例 |
| 3.4 | 知识有来源或依据 | 可追溯 |
| 3.5 | 知识密度与篇幅匹配 | 每段都有增量信息，无废话 |

### D4：工作流完整性（权重 15%）

是否定义了端到端工作流，包含正常路径、分支路径和异常处理。

| # | 检查项 | 通过标准 |
|---|--------|---------|
| 4.1 | 有完整的端到端流程 | 起点明确，终点可验证 |
| 4.2 | 有分支路径 | "如果 X 则走 A，否则走 B" |
| 4.3 | 有异常处理 | 错误/失败有处理指引 |
| 4.4 | 有回退/降级策略 | "无法完成时怎么办" |
| 4.5 | 流程可闭环 | 产出物有验收标准 |

### D5：输入输出清晰度（权重 10%）

用户和 AI 是否清楚该提供什么输入、能得到什么输出。

| # | 检查项 | 通过标准 |
|---|--------|---------|
| 5.1 | 声明了 Skill 需要的输入 | 明确列出需要什么 |
| 5.2 | 声明了 Skill 的产出物 | 明确列出产出什么 |
| 5.3 | 有输入示例 | 2-3 个具体输入示例 |
| 5.4 | 有输出格式定义 | 产出物格式可预期 |
| 5.5 | 输入输出有类型/约束 | 如"模块名必须是 kebab-case" |

### D6：资源利用（权重 10%）

对 scripts、references、assets 等附带资源的有效利用。

| # | 检查项 | 通过标准 |
|---|--------|---------|
| 6.1 | 引用了外部脚本/工具 | 如验证脚本、扫描脚本 |
| 6.2 | 引用了参考文档 | 如官方文档链接、技术规范 |
| 6.3 | 资源路径正确可达 | 无死链 |
| 6.4 | 资源与 Skill 内容互补 | 非重复引用 |
| 6.5 | 资源按需加载 | 非全量预加载 |

> **N/A**：如果 Skill 本身不需要附带资源，此维度标注 N/A，权重按比例分配到其他维度。

### D7：写作质量（权重 10%）

结构清晰、可读性强、表述精确。

| # | 检查项 | 通过标准 |
|---|--------|---------|
| 7.1 | 结构层次清晰 | H1->H2->H3 递进，无跳级 |
| 7.2 | 使用结构化格式 | 关键信息用表格，步骤用列表 |
| 7.3 | 表述精确无歧义 | 无"大概/可能/看情况" |
| 7.4 | 术语一致 | 全文同一术语同一写法 |
| 7.5 | 篇幅精炼 | 无三行以上重复内容 |

### D8：范围与聚焦（权重 10%）

专注解决一类问题，既不过宽也不过窄。

| # | 检查项 | 通过标准 |
|---|--------|---------|
| 8.1 | Skill 有明确的职责边界 | 边界清晰 |
| 8.2 | 不与其他 Skill 职责重叠 | 职责无大面积重叠 |
| 8.3 | 覆盖了该领域的核心场景 | 非只覆盖特例 |
| 8.4 | 不过度泛化 | 有明确的不适用场景 |
| 8.5 | 有组合使用指引 | 声明常见组合 |

## 评分计算

**综合得分 = D1x0.15 + D2x0.15 + D3x0.15 + D4x0.15 + D5x0.10 + D6x0.10 + D7x0.10 + D8x0.10**

等级映射详见 `templates/dimensions.md` 底部「等级映射」章节。

---

## 评估执行流程

```
1. 读取目标 Skill 的 SKILL.md 完整内容
2. 列出附带资源（scripts/、references/、assets/），存在关键资源时读取内容
3. 按 D1-D8 逐维度打分（评分细则参照 templates/dimensions.md），每个评分附带具体证据引用
4. 计算加权综合得分和等级
5. 对低于 7 分的维度给出：问题 + 影响 + 可执行建议
6. 输出评估报告
7. 持久化：将报告保存到 {评估结果根目录}/{Skill名称}/track1_{YYYY-MM-DD_HHmmss}.md
8. 历史对比：若该 Skill 存在历史评估报告，输出趋势分析
```

---

## 结果持久化

评估完成后，自动将报告保存为 Markdown 文件：

- **保存路径**：`{评估结果根目录}/{Skill名称}/track1_{YYYY-MM-DD_HHmmss}.md`
- **默认根目录**：`./eval-results/`（相对于当前工作目录）
- **路径不存在时**：自动创建目录
- **保存内容**：完整评估报告（评分表 + 问题建议 + 历史趋势章节）

---

## 历史趋势对比

当同一 Skill 存在历史评估报告时，在报告末尾附加「历史趋势」章节：

```markdown
## 历史趋势

| 日期 | 综合得分 | 等级 | D1 | D2 | D3 | D4 | D5 | D6 | D7 | D8 |
|------|---------|------|----|----|----|----|----|----|----|----|
| 2026-06-07 | 7.8 | A | 8 | 7 | 9 | 8 | 7 | 7 | 8 | 8 |
| 2026-05-20 | 6.5 | B | 6 | 6 | 8 | 7 | 5 | 7 | 7 | 6 |

### 变化分析
- 综合得分：6.5 → 7.8（+1.3，等级 B→A）
- 进步最大：D5（+2），D1（+2）
- 退步维度：无
- 持续薄弱：D2（连续两次 <= 7）
```
