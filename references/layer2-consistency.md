# 第二层：分类一致性评估

评估同一分类下文件之间是否协调——有无冲突、重叠、遗漏。LAYER2_DIMENSIONS 个加权维度，SCORE_RANGE 分制，S 级（>= PASSING_SCORE）为唯一达标等级。

> **前置条件**：第一层（文件质量评估）该分类下所有文件达标后，方可执行本评估。如有文件评估 < PASSING_SCORE，必须先修复。近 SKIP_DAYS 天内已做过第一层且全部 >= PASSING_SCORE 且无文件变更，可跳过。
> **评估单位**：以"分类"为单位执行。每个分类（SKILL.md + 其子文档）作为整体评估一次。

## 评估范围

### 分类发现

1. 递归扫描被评估体系根目录下所有 `SKILL.md` 文件，每个定义一个"分类"
2. 每个分类 = SKILL.md 所在目录 + 其子目录下所有 `.md` 文件
3. 不属于任何分类的 `.md` 文件 → 标记为"根目录文件"（仅第三层评估）
4. 分类名：入口文件所在目录名；若入口文件在根目录，则使用入口文件名（不含扩展名）

### 评估前提

| 条件 | 说明 |
|------|------|
| 第一层该分类全部达标 | 所有文件综合得分 >= 9.0（S 级） |
| 可跳过条件 | 近 30 天内已做过第一层且全部 >= 9.0 且无文件变更 |
| 不可跳过 | 第一层有文件 < 9.0 时，必须先修复 |

## 8 维度评估框架

### D1(职责边界)：职责边界（权重 15%）

分类内文件职责无重叠、无遗漏，每个文件各管一块。

| # | 检查项 | 通过标准 |
|---|--------|---------|
| 1.1 | 文件间职责无大面积重叠 | 无 3+ 处重复定义 |
| 1.2 | 分类领域核心场景无遗漏 | 该分类应覆盖的场景均有对应文件 |
| 1.3 | 每个文件聚焦单一主题 | 单个文件只做一件事 |
| 1.4 | 无"万能文件" | 无单文件承担 3+ 个独立主题 |
| 1.5 | 职责划分粒度合理 | 不过细（一个知识点一个文件）也不过粗（一个大而全文件） |

评分：9-10 职责清晰无重叠无遗漏 + 粒度合理 | 7-8 少量重叠（1-2 处）但无遗漏 | 5-6 存在明显重叠或遗漏 | 3-4 多处重叠且遗漏 | 1-2 职责划分混乱

### D2(术语一致)：术语一致性（权重 10%）

同一概念在分类内所有文件中使用统一术语。

| # | 检查项 | 通过标准 |
|---|--------|---------|
| 2.1 | 核心术语全文统一 | 同一概念不会在不同文件中叫不同名字 |
| 2.2 | 缩写使用一致 | 同一术语不会一处用全称一处用缩写 |
| 2.3 | 中英文术语一致 | 不会一处用中文一处用英文 |
| 2.4 | 命名风格统一 | 文件名、变量名、类名风格一致 |

评分：9-10 全部术语统一 + 有术语表 | 7-8 核心术语统一，少量非关键术语不一致 | 5-6 存在关键术语不一致（2-3 处）| 3-4 大量术语不一致 | 1-2 术语混乱，无法确定标准

### D3(交叉引用)：交叉引用（权重 10%）

文件间引用正确、可达，引用内容与目标文件匹配。

| # | 检查项 | 通过标准 |
|---|--------|---------|
| 3.1 | 文件间引用路径正确 | "详见 05-MapStruct" 对应的文件存在 |
| 3.2 | 引用内容与目标匹配 | 引用描述与目标文件实际内容一致 |
| 3.3 | 无循环引用 | A 引用 B，B 又引用 A 形成死循环 |
| 3.4 | 双向引用合理 | 相关文件间有适当的互相引用 |

评分：9-10 所有引用正确可达 + 内容匹配 + 无循环 | 7-8 引用路径正确但少量内容不匹配 | 5-6 存在断链或引用不匹配 | 3-4 多处断链 | 1-2 引用体系混乱

### D4(知识覆盖)：知识覆盖度（权重 15%）

分类领域核心场景无遗漏，知识体系完整。

| # | 检查项 | 通过标准 |
|---|--------|---------|
| 4.1 | 核心场景全部覆盖 | 该分类应覆盖的核心场景均有对应文件 |
| 4.2 | 知识层次完整 | 基础概念 → 进阶实践 → 高级场景均有覆盖 |
| 4.3 | 边界场景有说明 | 常见边界情况和异常场景有专门文件或章节 |
| 4.4 | 与入口文件声明一致 | SKILL.md 声明的范围被子文档完整覆盖 |
| 4.5 | 无"空壳文件" | 每个文件有实质性内容，非占位符 |

评分：9-10 核心场景全覆盖 + 层次完整 + 边界场景有说明 | 7-8 核心场景覆盖但少量边界场景缺失 | 5-6 存在核心场景遗漏 | 3-4 大量遗漏 | 1-2 知识体系不完整

### D5(冗余检测)：冗余检测（权重 10%）

无跨文件大段重复，相同知识点集中定义、其他位置引用。

| # | 检查项 | 通过标准 |
|---|--------|---------|
| 5.1 | 无跨文件大段重复 | 同一段规范不会在 2+ 个文件中重复出现 |
| 5.2 | 重复内容已集中定义 | 共享知识点有唯一权威定义位置 |
| 5.3 | 其他位置使用引用 | 需要该知识点时引用而非复制 |
| 5.4 | 示例不重复 | 同一示例不会在多个文件中重复出现 |

评分：9-10 零冗余 + 集中定义 + 引用复用 | 7-8 少量冗余（1-2 处短段）| 5-6 存在明显冗余（3+ 处或大段重复）| 3-4 大量冗余 | 1-2 复制粘贴为主，无复用机制

### D6(层级结构)：层级结构（权重 10%）

编号/分组/命名逻辑一致，文件组织有序。

| # | 检查项 | 通过标准 |
|---|--------|---------|
| 6.1 | 编号规则一致 | 数字编号连续、无跳号 |
| 6.2 | 特殊分组一致 | 99- 前缀用于特殊分组（如工作流），规则统一 |
| 6.3 | 命名风格统一 | 文件名使用相同命名风格（如 kebab-case） |
| 6.4 | 目录结构合理 | 子目录划分逻辑清晰，不过深也不过平 |
| 6.5 | 排序逻辑可理解 | 文件排列顺序符合认知逻辑 |

评分：9-10 编号连续 + 分组一致 + 命名统一 + 排序合理 | 7-8 基本一致但少量不规则 | 5-6 编号跳号或命名风格不统一 | 3-4 组织混乱 | 1-2 无组织结构

### D7(元数据一致)：元数据一致性（权重 15%）

子文档 frontmatter 与入口文件路由表一致，无孤立文件、无幽灵引用。

| # | 检查项 | 通过标准 |
|---|--------|---------|
| 7.1 | 子文档 frontmatter 与路由表一致 | level/status/order 与 SKILL.md 路由表声明一致 |
| 7.2 | 无孤立子文档 | 每个子文档在 SKILL.md 路由表中有对应条目 |
| 7.3 | 无幽灵引用 | 路由表中引用的文件实际存在 |
| 7.4 | 子文档 description 触发条件与路由表匹配 | 触发条件覆盖路由表声明的使用场景 |
| 7.5 | 子文档间无职责重叠 | 同一分类内子文档无 3+ 处重复定义 |

评分：9-10 全部一致 + 无孤立/幽灵 + 无重叠 + 触发条件匹配 | 7-8 少量不一致（<10%子文档）但无孤立/幽灵 | 5-6 存在孤立子文档或幽灵引用 | 3-4 大量子文档与路由表不一致 | 1-2 无路由表或子文档完全无组织

### D8(工作流闭环)：工作流闭环（权重 15%）

入口文件声明的工作流被子文档完整覆盖，流程可闭环。

| # | 检查项 | 通过标准 |
|---|--------|---------|
| 8.1 | SKILL.md 声明的流程在子文档中有详细说明 | 主流程有对应子文档展开 |
| 8.2 | 工作流步骤与子文档对应 | 每个步骤有明确的子文档承载 |
| 8.3 | 分支流程有覆盖 | 异常/分支处理在子文档中有说明 |
| 8.4 | 端到端可闭环 | 从开始到结束的完整路径有文档支撑 |
| 8.5 | 子文档间流程衔接 | 前一步骤的产出是下一步骤的输入 |

评分：9-10 全流程覆盖 + 分支有说明 + 端到端闭环 + 衔接流畅 | 7-8 主流程覆盖但少量分支缺失 | 5-6 主流程有缺口 | 3-4 工作流与子文档脱节 | 1-2 入口文件声明的工作流无子文档支撑

## 评分计算

**加权总分 = D1×0.15 + D2×0.10 + D3×0.10 + D4×0.15 + D5×0.10 + D6×0.10 + D7×0.15 + D8×0.15**

> **等级映射**：所有层级通用，详见 `references/config.md`。

---

## 评估执行流程

```
1. 确认第一层该分类已全部达标
2. 读取该分类下所有文件内容（SKILL.md + 子文档）
3. 交叉比对：子文档 frontmatter vs SKILL.md 路由表
4. 逐维度评分（D1-D8），每个维度输出：评分 + 证据 + 问题列表
5. 计算加权总分和等级
6. 对低于 9 分的维度给出改进建议
7. 输出评估报告
8. 持久化：将报告保存到 {评估结果根目录}/{分类名称}/layer2_{YYYY-MM-DD_HHmmss}.md
9. 历史对比：若该分类存在历史评估报告，输出趋势分析
10. 自动修复：如分类未达标（加权总分 < PASSING_SCORE），执行自动修复（详见 `references/auto-fix.md`）
```
