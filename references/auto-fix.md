# 自动修复机制

> **核心原则**：任何一层未达标时，自动修复未达标文件/分类，无需询问用户，修复后重新评估，直到全部达标后才进入下一层。

---

## 流程图

```
评估 → 有未达标项？
  ├── 是 → 自动修复未达标文件/分类 → 重新评估该文件/分类 → 循环直到达标
  └── 否 → 进入下一层（或完成评估）
```

---

## 通用修复规则

| 规则 | 说明 |
|------|------|
| 不询问用户 | 发现未达标项后直接修复，不中断流程询问用户是否修复 |
| 按建议修复 | 依据评估报告中的改进建议逐项修复 |
| 最小改动原则 | 仅修改未达标维度涉及的内容，不做无关改动 |
| 修复后重评 | 修复完成后立即重新评估该文件/分类，确认是否达标 |
| 最大修复轮次 | 每个文件/分类最多修复 MAX_FIX_ROUNDS 轮，避免无限循环 |
| 修复轮次耗尽 | 仍不达标时输出警告，标记为"需人工介入"，跳过该文件/分类 |

---

## 各层修复行为

| 层级 | 修复对象 | 修复方式 | 达标条件 | 特殊处理 |
|------|---------|---------|---------|---------|
| 第一层 | 单个 .md 文件 | 按改进建议修改文件内容（元数据、结构、措辞等） | 综合得分 >= PASSING_SCORE | — |
| 第二层 | 分类内文件间关系 | 修复术语不一致、交叉引用断链、冗余、元数据不匹配等 | 加权总分 >= PASSING_SCORE | — |
| 第三层 | 体系架构 | 仅输出改进路线图，不自动修改架构 | 加权总分 >= PASSING_SCORE | 架构变更需人工决策，不适合自动修复 |

---

## 第一层修复策略

| 未达标维度 | 修复策略 | 示例 |
|-----------|---------|------|
| D1 元数据质量 | 补充/修正 frontmatter 字段 | 添加缺失的 name/description/status/version |
| D2 执行引导清晰度 | 添加加载声明、预检清单、异常处理 | 补充 Pre-Flight 检查项 |
| D3 领域知识密度 | 补充专业知识和最佳实践 | 添加 do/don't 对照、具体示例 |
| D4 工作流完整性 | 补充分支路径和异常处理 | 添加"如果 X 则走 A，否则走 B" |
| D5 输入输出清晰度 | 补充输入示例和输出格式 | 添加 2-3 个具体输入示例 |
| D6 资源利用 | 添加资源引用或标注 N/A | 补充脚本/文档引用路径 |
| D7 写作质量 | 优化结构、消除歧义、统一术语 | 重组标题层级、替换模糊表述 |
| D8 范围与聚焦 | 明确职责边界和不适用的场景 | 添加"本 Skill 不适用于 X" |

### 第一层修复约束

| 约束 | 说明 |
|------|------|
| 最小改动 | 仅修改未达标维度涉及的内容，不重构整个文件 |
| 保留原意 | 不改变文件的核心意图和功能定位 |
| 不引入新问题 | 修复一个维度时不得导致其他维度降分 |
| 可追溯 | 每次修复记录修改内容和原因 |

---

## 第二层修复策略

| 未达标维度 | 修复策略 | 示例 |
|-----------|---------|------|
| D1 职责边界 | 合并重叠文件或拆分万能文件 | 将职责重叠的内容合并到权威文件 |
| D2 术语一致性 | 统一术语为最常用写法 | 全文替换不一致的术语 |
| D3 交叉引用 | 修复断链、补充缺失引用 | 更新文件路径引用 |
| D4 知识覆盖度 | 补充遗漏场景的子文档或章节 | 添加缺失的核心场景说明 |
| D5 冗余检测 | 集中定义重复内容，其他位置改为引用 | 将重复段落替换为"详见 X" |
| D6 层级结构 | 统一编号规则和命名风格 | 修正跳号、统一 kebab-case |
| D7 元数据一致性 | 同步 frontmatter 与路由表 | 补充缺失的 frontmatter 字段 |
| D8 工作流闭环 | 补充缺失的工作流步骤文档 | 添加分支流程的子文档说明 |

### 第二层修复约束

| 约束 | 说明 |
|------|------|
| 最小改动 | 仅修复一致性问题，不重构分类结构 |
| 保留内容 | 不删除有价值的知识内容，仅整合或引用化 |
| 不引入新问题 | 修复一致性时不得导致第一层已达标文件降分 |
| 可追溯 | 每次修复记录修改内容和原因 |

---

## 第三层修复策略

> 第三层评估未达标时，**不自动修改架构**，而是输出详细改进路线图供人工决策。

```
评估完成 → 体系架构达标？
  ├── 是 → 评估完成，输出成熟度等级
  └── 否 → 输出改进路线图（紧急/短期/中期）
           → 标记为"需人工决策"
           → 评估流程结束
```

### 改进路线图格式

| 优先级 | 时间范围 | 内容 |
|--------|---------|------|
| 紧急 | 1 周内 | BLOCK 级维度（评分 <= 4）的修复方案 |
| 短期 | 1 月内 | 评分 5-7 分维度的改进方案 |
| 中期 | 1 季度内 | 评分 7-8.9 分维度的优化方案 |

> **为什么第三层不自动修复**：体系架构变更（如合并/拆分 Skill、调整分层、修改路由机制）影响全局，需要人工评估副作用后决策。自动修复可能导致第一层和第二层已达标的内容降分。
