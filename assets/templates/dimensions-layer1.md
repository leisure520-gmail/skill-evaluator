# 第一层：文件质量评估维度

> **适用范围**：第一层（文件质量评估）。第二层评分标准见 `assets/templates/dimensions-layer2.md`，第三层评分标准内嵌于 `references/layer3-architecture.md`。

从以下 **8 个维度** 对每个文件打分，每个维度 0-10 分。此文件是第一层所有评估模式共用的唯一评分标准。

> **评估深度**：入口文件（SKILL.md）和有 frontmatter 的子文档使用完整评估（D1-D8）；无 frontmatter 的子文档使用轻量评估（D3+D7）。详见 `references/layer1-quality.md` 评估深度分级。

---

### 权重设计依据

权重分配遵循**核心能力优先**原则：

- **15% 权重（D1/D2/D3/D4）**：这四个维度决定 Skill 的核心价值——元数据质量决定可发现性，执行引导决定可用性，领域知识决定不可替代性，工作流决定完整性。它们是 Skill 能否被正确触发和执行的关键，因此赋予更高权重。
- **10% 权重（D5/D6/D7/D8）**：这四个维度影响 Skill 的易用性和规范性，但属于"锦上添花"——即使输入输出描述不够完美，Skill 仍可使用；即使写作质量一般，核心功能不受影响。

> **设计哲学**：权重差异不大（15% vs 10%），避免单一维度过度主导总分。1.5:1 的比例确保核心维度有足够区分度，同时辅助维度仍有影响力。

---

### D1(元数据)：元数据质量（权重 15%）

评估 YAML frontmatter 中的 `name` 和 `description`：

| 分数 | 标准 |
|------|------|
| 0-3 | 缺失、模糊或泛泛而谈（如 "Replace with description"） |
| 4-6 | 描述了 Skill 的功能，但缺少触发条件 |
| 7-8 | 清晰描述功能并包含使用场景 |
| 9-10 | 精确描述，同时包含正向触发条件和反向排除条件（如 "TRIGGER when... DO NOT TRIGGER when..."） |

### D2(执行引导)：执行引导清晰度（权重 15%）

Skill 被加载后，Agent 是否清楚该怎么执行？面对不同输入能否正确决策？

| 分数 | 标准 |
|------|------|
| 0-3 | 加载后 Agent 仍不知道该做什么，缺少具体指令 |
| 4-6 | 有基本执行步骤，但面对不同用户输入时缺少分支引导 |
| 7-8 | 对不同场景有清晰的执行路径，说明了何时需要追问用户 |
| 9-10 | 执行引导完备：覆盖多种输入场景的分支逻辑，明确执行边界（该做什么、不该做什么），包含异常情况的处理指引 |

### D3(领域知识)：领域知识密度（权重 15%）

Skill 是否内嵌了通用 Agent 不具备的专业知识？

| 分数 | 标准 |
|------|------|
| 0-3 | 无专业知识，只是包装了基础指令 |
| 4-6 | 包含一些领域特定的指导或约定 |
| 7-8 | 有丰富的专家知识、数据模型或最佳实践 |
| 9-10 | 深度的、难以获取的领域专业知识，包含细致的决策逻辑 |

### D4(工作流)：工作流完整性（权重 15%）

Skill 是否定义了清晰的端到端工作流？

| 分数 | 标准 |
|------|------|
| 0-3 | 无工作流，只是单个操作或模糊指令 |
| 4-6 | 列出了部分步骤，但缺少异常处理或分支逻辑 |
| 7-8 | 完整的多步骤工作流，步骤顺序清晰 |
| 9-10 | 健壮的工作流，包含分支、异常处理和迭代循环 |

### D5(输入输出)：输入输出清晰度（权重 10%）

用户是否知道该提供什么、能得到什么？

| 分数 | 标准 |
|------|------|
| 0-3 | 输入和输出均未描述 |
| 4-6 | 部分描述，用户需自行推断 |
| 7-8 | 清晰的输入要求和输出格式，附有示例 |
| 9-10 | 明确的输入输出契约，包含多个示例和边界情况 |

### D6(资源利用)：资源利用（权重 10%）

Skill 对附带资源（scripts、references、assets）的利用程度如何？

| 分数 | 标准 |
|------|------|
| 0-3 | 明显需要资源却未提供任何附带资源 |
| 4-6 | 有部分资源但利用不足或组织混乱 |
| 7-8 | 资源利用合理：脚本用于确定性任务，references 用于领域文档 |
| 9-10 | 资源设计优秀，遵循渐进式披露；SKILL.md 精简，配套文件丰富 |
| N/A | Skill 确实不需要附带资源（按 7 分基线计分） |

### D7(写作质量)：写作质量（权重 10%）

SKILL.md 结构是否清晰、是否易于 Agent 理解和执行？

| 分数 | 标准 |
|------|------|
| 0-3 | 组织混乱、表述模糊或指令自相矛盾 |
| 4-6 | 可读但结构或简洁性有待提升 |
| 7-8 | 组织良好，标题清晰，祈使语气，逻辑流畅 |
| 9-10 | 优秀的技术写作：可扫读、精确、无冗余 |

### D8(范围聚焦)：范围与聚焦（权重 10%）

Skill 是否专注解决一类问题，既不过宽也不过窄？

| 分数 | 标准 |
|------|------|
| 0-3 | 过于宽泛（试图包揽一切）或过于琐碎（不值得做成 Skill） |
| 4-6 | 范围合理但存在功能蔓延或缺少边界定义 |
| 7-8 | 聚焦于单一且连贯的问题域 |
| 9-10 | 范围精确，明确说明了哪些不在范围内 |

---

### 评分计算

#### 完整评估（D1-D8）

**综合得分 = D1×0.15 + D2×0.15 + D3×0.15 + D4×0.15 + D5×0.10 + D6×0.10 + D7×0.10 + D8×0.10**

#### 轻量评估（D3+D7）

无 frontmatter 的子文档仅评估 D3 和 D7，按比例换算为 10 分制：

**综合得分 = D3×0.6 + D7×0.4**
